# 鱼缸

开发者与 Agent 请从 [agent.md](agent.md) 和 [spec 规范索引](spec/README.md)开始。

DSH 侧栏里的正面草缸：工作时积累自动鱼食，闲时看鱼巡游、培育后代、收集稀有来客，也能修剪和繁殖水草。

## 鱼缸与投喂

- 正面草缸视角，18 种鱼使用写实透明素材；鱼体和鳍缘随游动形变，鱼会巡游、转向和追食。优先使用 WebGL，无法使用时回退 Canvas 2D，并遵循系统减少动效设置。当前仍是图集驱动的近似体积效果，并非完整三维鱼体或 3A 画面。
- 每 **20,000 新增 token = 1 粒自动鱼食**。包含缓存读取，按会话累计用量计算；初见某会话只记基线，不补发历史鱼食。
- 点「投喂」撒 3 粒，点击水中撒 1 粒，手动投喂免费，不扣自动储备。吃饱的鱼忽略多余食物，鱼食会沉底。
- 鱼饿时才动用自动储备，开着页面时，小鱼群每次补 1 粒，大鱼群每 5 秒最多补至水中 4 粒。饥饿约 24 小时到顶，饿到顶再持续 72 小时死亡；每粒食物降低 3.2 个百分点饥饿并增加 6.5 个百分点成长。稳定自动投喂时理论上约每鱼每天 31 粒（此前约 25 粒，实际取决于鱼是否吃到和储备是否充足）。
- 水景包含分层水草、叶脉纹理、缓坡细沙、沉木、卵石、气泡与轻微水面反光。主要空间留给鱼缸，玩法进度在紧凑状态栏中，鱼册和规则默认折叠。 页头、投喂按钮和缸外面板跟随 DSH 的浅色或深色主题，缸内水景独立渲染。

## 亲鱼、产卵与育苗

- 两条**成长至少 85%、饥饿不高于 78%**的鱼自动配对，同种优先。混合品种配对时，后代只采用一个完整鱼种的形象。
- 投喂任一亲鱼，亲密度增加 1；达到 **8 次**后产下一窝卵，每窝孵化一条鱼苗，产卵冷却 **2 小时**。同一对亲鱼会尽量保持配对，亲鱼不再符合条件时重新选择。
- 卵约 **20 分钟**孵化。孵化期间每次喂亲鱼再缩短 **2 分钟**，最短孵化时间为产卵后 1 分钟。水草也能减少初始孵化时长。
- 普通亲鱼的后代：**常见 82%、稀有 16%、传说 2%**；连续 7 窝常见后，第 8 窝保底稀有以上，传说概率仍为 2%。
- 稀有以上亲鱼有 50% 概率直接传承自己的鱼种，其余按基础概率抽取；未传承时，普通后代可能返祖成常见品种。保底根据最终后代的稀有度结算。
- 卵的鱼种在产卵时确定并保存，刷新不会重抽。鱼的数量不设上限，到时直接孵化；亲鱼离缸或死亡也不会丢掉已有的卵。

## 溪流来客与收藏

- 本次更新后，每 **300,000 新增 token** 获得 1 次寻访机会，和自动鱼食同时累计，不额外扣食物；更新前的历史总量不会补发寻访。
- 点击「迎接来客」使用机会。首章优先带回当前稀有度里未收录的鱼；连续 3 次重复后第 4 次必带回新品种。未触发新品种保底时，来客概率为**常见 75%、稀有 22%、传说 3%**；连续 9 次常见后，第 10 次保底稀有以上。繁殖与来客的保底独立保存。
- **常见 6 种**：蓝白斗鱼、红龙孔雀鱼、锦鲤神仙鱼、宝莲灯、蓝松石七彩神仙、荷兰凤凰。
- **稀有 3 种**：电光蓝阿卡拉、火焰丽丽、珍珠马甲。
- **传说 3 种**：白金龙鱼、黄金七彩神仙、黑天使神仙鱼。
- 鱼缸与收藏池均不设数量上限。新来客直接游入鱼缸，并显示品种和入缸提示。旧版因满缸存入收藏池的鱼继续保留，展开鱼册可「全部接回鱼缸」。
- 鱼册的「缸内居民」按品种合并：每组显示品种、稀有度、条数和代数范围，展开后才能逐条「安置」，也可以整组一次安置到收藏池。收藏池暂停饥饿和繁殖；接回时保持身份、鱼种、成长和代数，饥饿不高于 50%。发现过的品种永久记在鱼册里，鱼离缸也不删除记录。

## 自动扩容

鱼的数量不设上限。累计 token 每达到 **1,000,000** 的新里程碑，自动扩容一次，水域等级加 1；扩容不扣除鱼食或寻访机会，已有累计用量也会解锁水域。已解锁的空间不会因统计来源切换而回退。

除了扩容，每到水域 **50 / 100 / 150 … 级**会更换缸内造景，依次加入石坡水草、岩洞、沉木根系，后续继续按等级变换布局。造景不影响鱼的活动。鱼群拥挤时画面会更早拉远，让更多鱼同屏，不隐藏或删除鱼。饥饿、成长和死亡仍按每条鱼结算。

## 图鉴第二章、捕猎与小龟

- 集齐最初 **12 种鱼**后，自动解锁第二章 **6 种**：奥斯卡地图鱼、多鳍鱼、虎皮鱼、斑马鱼、波氏彩虹鱼和熊猫鼠鱼。来客在相同稀有度里优先带回第二章尚未发现的品种，原有保底继续有效。
- 生态捕猎在第二章解锁，**默认关闭**，可在折叠规则中开启。只在页面打开时运行；离线不捕猎。缸内至少16条鱼时，成长≥85%、饥饿≥55%、过去1小时未捕猎的地图鱼或多鳍鱼，会追逐普通、自繁、成长≤30%的鱼苗。成年鱼、稀有鱼和初始鱼受到保护。投喂会打断追逐。
- 达成 **孵化3条鱼苗、水草5丛、累计100万token**，自动奖励一只永久小龟。小龟在缸底慢慢巡视、吃沉底鱼食，不计入鱼的数量，也不会饿死。奖励和位置随存档保存，刷新不会重复领取。
- ⓘ 说明气泡支持鼠标悬停、点击与键盘聚焦；点外部或按 Escape 关闭，手机上不会超出屏幕。

## 水草成长与分株

- 水草每天自然成长 **18%**，鱼每次实际吃到食物再增加 **0.2%**。离线也会成长，长势上限为 100%。
- 长势至少 **75%**时，可以「修剪分株」：长势减少 40%，获得 1 株分株。再点「种下分株」，增加一丛水草，在前景生根。
- 初始 **3 丛**，最多 **8 丛**。每新增一丛，初始孵化时间缩短 **4%**，最多缩短 **20%**；已在孵化的卵不追溯重算。

## 保存与升级

主存档写入主机 JSON 文件（默认 `~/.dsh/fish-tank/tank.json`），浏览器 `localStorage`（`dsh.fish-tank.v1`）保留缓存。鱼册、收藏池、孵化、保底和水草也随主机文件保存。关闭鱼缸后，重新打开会按储备结算饥饿、成长、繁殖、孵化和水草成长，最多结算 14 天。

2.0 自动读取旧鱼缸，保留原有鱼、食物储备和 token 基线。首次写入新格式前，旧存档备份到 `dsh.fish-tank.before-v3`。新格式和繁殖变化见 [升级说明](UPGRADING.md)。

## 数据保存在哪

- **主机文件**：插件的主机半侧在 `/fish-tank/state` 提供读写接口，把鱼缸存成一个 JSON 文件，默认 `~/.dsh/fish-tank/tank.json`（`DSH_HOME` 下）。页面打开时先读文件，状态变化后约每几秒写回一次，切走页面时立即写回。
- **浏览器缓存**：`localStorage` 键 `dsh.fish-tank.v1` 继续保留，同一浏览器下次打开更快；文件和浏览器数据不一致时按 `updatedAt` 取较新的，Host 会拒绝比文件更旧的快照。
- **换浏览器 / 清站点数据 / 换机器**：打开页面时会从文件恢复；换机器把 `tank.json` 复制到同路径（或下面配置的路径）即可。
- 界面不显示文件路径或链接。详细规则内只显示保存模式和用量来源；无法连接主机时明确显示只保存在此浏览器。

### 自定义路径（放到同步盘或项目目录）

在 profile 的 patch 里给这一行加配置，然后重启 DSH：

```yaml
# ~/.dsh/profiles/desktop/cordis.patch.yml
- id: fish-tank
  config:
    statePath: /Users/you/iCloud/fish-tank/tank.json
```

`statePath` 必须是绝对路径。主机半侧的改动要**重启一次 DSH** 才生效（页面半侧会热替换）。


## 测试与素材

```sh
npm ci
npm run build
npm test
```

`client.js` 是 DSH 加载的生成产物；修改 `src/` 或 `assets/` 后执行 `npm run build`。`npm test` 会先构建，再运行模拟、存档、账号适配、渲染回归及页面测试；页面测试使用本地开发依赖，也可通过 `DSH_CHECKOUT` 指向 DSH 源码目录。这些测试不调用模型。

`assets/` 保存三组鱼图集、水草及鱼缸背景与前景，构建时内嵌到客户端，运行时无需联网或额外资源路由。`node scripts/embed-fish-atlas.mjs` 保留为构建兼容入口。架构和已知限制见 [架构说明](spec/architecture.md)，整体视觉目标及缺口见 [视觉路线](spec/visual-requirements.md)，本次合并后的检查见 [真实 DSH 验收记录](spec/acceptance.md)。

## 账号用量和跨端同步的实际范围

默认模式仍是主机 JSON 文件加浏览器缓存。连接**同一台 DSH 主机**的浏览器可以恢复同一份鱼缸；在不同设备独立运行 DSH，**仅登录相同 DeepSeek 账号并不会自动共享鱼缸**。

当前仓库的 `deepseekAccount` 只公开账号资料、余额等操作，没有账号累计 token 或通用云存档接口。插件不会猜测接口、抓取余额当用量，也不会把本机文件标成云端。未接入时，界面明确标注「当前主机会话统计」。

已提供可配置的 Host 接入层，但**仓库没有已部署云服务，默认不启用**：

- `accountUsagePath`：由账号后端确认并实现的真实路径，仅允许位于已登录 Platform 的同一来源。响应必须为 `{accountId, totalTokens}`；首次账号读取只建立奖励基线，后续增量兑换鱼食和寻访，水域使用账号累计值。账号源接管后，停止重复累计本机会话。
- `cloudStateURL`：独立的 HTTPS 账号存档服务地址；Host 从 `deepseekAccount.getPlatformSession()` 获取稳定账号 ID，专用访问密钥通过环境变量 `DSH_FISH_TANK_CLOUD_TOKEN` 提供。DeepSeek 登录凭据不会转发给该服务。
- 云服务 GET 返回 `{accountId, revision, tank, totalTokens?}`，POST 接收 `{accountId, revision, tank}`；服务端必须校验密钥所属账号并使用 revision 拒绝旧写入（409）。Host 同样拒绝不匹配账号和旧版本。失败时保留本地数据，不伪装成同步成功。
- `totalTokens` 必须来自可信的账号用量后端，不应由终端随意上报。若云服务没有用量，鱼缸可同步，但账号总量仍明确标记为未接入。
- 验证了两个独立客户端通过模拟账号服务共享同一存档及冲突保护；尚未连接真实账号用量接口或部署云存档。启用前需要提供真实服务地址、响应约定和专用凭据。
