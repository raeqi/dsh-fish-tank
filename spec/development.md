# 开发与验证规范

本规范适用于 DSH 鱼缸插件的源码、渲染素材、存档格式和宿主适配。目标是在扩展鱼群与视觉表现时维护核心链路、模块边界、性能和已有用户数据。以下是后续改动的要求，不表示当前所有测试或保护已经实现。

## 核心链路

会话用量经宿主适配与账本转换为储备；手动或自动投喂产生鱼食，模拟推进吃食、成长、饥饿、繁殖、死亡、水草等状态，再保存到浏览器缓存及配置的宿主存储。渲染和页面消费同一场景，不得改变这些业务结果。

- 保留 18 种鱼的持久化索引、现有玩法和用户状态。任何规则变化须同步说明、升级兼容策略与测试，不得悄悄改变旧存档的含义。
- 对受影响链路验证正常、边界及异常：初始化、会话数据未就绪、用量增量、离线结算、投喂、吃食、重启和失败恢复；新增功能测试应断言可观察结果，而非复制实现细节。
- 会话首次出现作为基线、仅遍历 `ids` 可能漏掉子会话，以及离线结算最多 14 天是当前限制；不能把这些限制写成已解决。调整前应建立真实宿主契约和回归用例。
- 区分模块测试、DOM/Canvas 模拟与真实 DSH 检查；真实宿主需要使用隔离配置和合成数据验证交互、状态及重启，未做的步骤单独标记。

## 模块解耦

- `src/core/` 表达鱼缸状态、规则和可测试的计算，不依赖 React、DOM、Canvas、WebGL 或 DSH 对象；宿主会话格式在 `src/host/` 适配。跨层只传递明确数据和事件。
- `src/renderer/` 消费场景快照、时间和画布上下文；图集、场景、鱼体、效果和画质策略按职责演进，不写持久状态或反向依赖页面。素材与鱼种映射集中维护，保持现有索引兼容。
- `src/ui/` 负责交互、展示、画布生命周期与宿主同步；`index.js` 和 `account-source.js` 负责 Host 路由及可选账号源。不要把宿主凭据传给客户端。
- 模块内部也按能力边界分解，避免一个文件承担不相关的规则、显示和 I/O；接口优先传入所需依赖，避免全局状态和循环依赖。新抽象须服务明确需求，删除不再使用的过渡代码。

## 性能验证

现有 `npm test` 是功能和回归测试，**不是性能基准**；当前没有持续运行的性能基准或已确认的统一帧率预算。涉及模拟复杂度、鱼群数量、每帧绘制、材质、资源加载或持久化频率的改动，合并前必须：

1. 在明确的目标设备和真实 DSH 桌面宿主上，以相同窗口大小、设备像素比、画质与测试数据采集改动前后基线；记录硬件、系统、DSH/Electron 版本、运行时长和预热条件。
2. 覆盖 3 条鱼、18 条鱼以及代表实际目标的大鱼群，并检查无鱼、窗口缩放、后台/恢复和 Canvas 回退；鱼群数量不能用悄悄删除数据或限制玩法来换取帧率。
3. 报告帧时间 p50、p95、最长值和采样时长，以及可采集的 CPU、GPU 与内存；明确浏览器帧间隔、GPU 耗时和模拟计算耗时的区别。固定环境下的自动基准与回归阈值应随性能相关功能建立并纳入持续验证。
4. 将结果与该设备约定的预算及基线比较；预算尚未确定或无法测试时写明未测与影响，不得声称性能达标。长时稳定性需单独测试，短样本不能替代。

## 持久化与恢复

默认数据是 Host JSON 与浏览器 `localStorage` 缓存；可选云服务使用账号身份与 revision。客户端状态使用 version 3 / featureVersion 2，鱼种索引、鱼群、收藏、鱼食、用量基线和玩法进度均属于用户数据。

- 持久化变更必须检查旧版本读取、新版本写回、原数据备份、旧客户端兼容、失败和回退；不截断多于 8 条鱼的 v2.1 存档。格式变化须说明版本、迁移、备份与回退策略。
- 测试读取失败、数据损坏、新版本未知、写入失败、旧快照、重复请求、切账号、跨窗口及同时写入。未知结果先对账；不得因失败静默重建或覆盖原数据。
- 当前浏览器保存前的快照比较并非原子操作，Host 内的写入队列也不能证明跨进程/跨机器互斥；新增并发保护需验证真实边界，不得以时间戳或单元测试冒充全局一致性。
- 实测前使用独立 `DSH_HOME`、Electron 用户目录及合成数据；不提交真实存档、密钥、会话或未脱敏日志。确需操作用户数据时先明确备份和回退。

## 构建、文档与交付

安装依赖运行 `npm ci`，修改源码或素材后执行 `npm run build`，提交与源码一致的生成物 `client.js`，再运行 `npm test`。按变更补充上述真实宿主、性能和存档验证；不要使用 DeepSeek 进行 token 消耗测试，必要的模型实测使用用户指定的本地 `qwen3.59b`。

`spec/` 是项目规范：每份文档应独立交代适用范围、关键事实、约束、当前状态、失败/边界和验证方法，并将目标与实际完成情况分开。变更实现、契约或架构时同步对应规范和可编辑架构图，检查链接；过时的过渡截图、录屏、临时报告及无引用的旧实现应移除，不能让规范依赖它们。提交说明记录具体变更、验证、未完成项和风险。
